# bible_converter

Compiles Bible JSON translations (KJV, WEB, ASV, and future ones) into one
ObjectBox database file per translation (`kjv.mdb`, `web.mdb`, `asv.mdb`).

Each output is a complete, self-contained ObjectBox store: one `BibleVersion`
record carrying the translation's full metadata, plus one `Verse` row per
verse. The converter is a build step — it is not part of the app bundle.

The long-form explanation (data model, design decisions, app-side bundling) is
in [`docs/bible_objectbox_converter.md`](../../docs/bible_objectbox_converter.md).
This file is the working reference for the tool as it actually exists.

## Layout

```
tools/bible_converter/
  pubspec.yaml              # bible_converter, objectbox + path, build_runner + generator
  bin/convert.dart          # CLI entry point
  lib/model.dart            # @Entity BibleVersion, @Entity Verse
  lib/json_reader.dart      # JSON -> entities (metadata mapping + verse mapping)
  lib/objectbox_writer.dart # native library loading, temp store, data.mdb path
  lib/converter.dart        # read -> write in batches -> close -> copy data.mdb
  lib/objectbox.g.dart      # generated by build_runner, committed
  lib/objectbox-model.json  # ObjectBox entity/property ids, committed
  input/                    # kjv.json, web.json, asv.json (sources, committed)
  outputs/                  # kjv.mdb, web.mdb, asv.mdb (build artifacts)
```

## Prerequisites

- Dart SDK (see `environment.sdk` in `pubspec.yaml`).
- **The ObjectBox native library at `native_libs/objectbox.dll` in the repo
  root.** One shared copy for the whole repo; never add a second copy inside
  this tool.

ObjectBox 6.x has no API to pass a native library path — `loadObjectBoxLib()`
takes no arguments and searches `<cwd>/lib/objectbox.dll`, then a bare
`objectbox.dll` lookup. So `ensureObjectBoxLibraryLoaded()` in
`lib/objectbox_writer.dart` walks up from the current directory to find
`native_libs/objectbox.dll`, switches into that folder for the duration of the
load, and restores the working directory afterwards. The load is cached per
process, so this happens once.

On Windows the DLL must match the architecture of the `dart` executable — a
64-bit SDK needs the 64-bit DLL. A mismatch fails as
`Failed to load dynamic library 'objectbox.dll'` with error code 126.

## Setup

```bash
cd tools/bible_converter
dart pub get
```

## Converting

The CLI takes three flags, all required:

| Flag       | Meaning                                                        |
| ---------- | -------------------------------------------------------------- |
| `--input`  | Path to the source JSON                                        |
| `--output` | Path for the compiled `.mdb` (its parent folder is created)    |
| `--code`   | Translation code, written as `versionCode` on every verse      |

One translation:

```bash
dart run bin/convert.dart --input input/kjv.json --output outputs/kjv.mdb --code kjv
dart run bin/convert.dart --input input/web.json --output outputs/web.mdb --code web
dart run bin/convert.dart --input input/asv.json --output outputs/asv.mdb --code asv
```

All three (Git Bash):

```bash
for t in kjv web asv; do
  dart run bin/convert.dart --input input/$t.json --output outputs/$t.mdb --code $t || exit 1
done
```

`--code` is not cosmetic: it is the only link between a `Verse` row and its
`BibleVersion` record, and the app will query by it. Use `kjv`, `web`, `asv` —
values like `1.0` produce rows nothing can look up.

## Output

- One file per translation, named after its code: `outputs/kjv.mdb` (~9 MB),
  `outputs/asv.mdb` (~9 MB), `outputs/web.mdb` (~9 MB).
- The `.mdb` is the store's `data.mdb`, copied out of a temp store after the
  store is closed.
- Expected verse counts: KJV 31,102, ASV 31,102, WEB 31,103.

Treat `outputs/` as build artifacts: regenerate, don't edit. Do not hand-edit a
`.mdb`, and never copy a converter `.mdb` over the mobile app's own store — it
holds the app's notes/drafts and uses the app's model. See the guide's
app-side section for how the translations reach the app.

## Verifying a build

```bash
dart analyze lib bin
ls -l outputs
```

A correct run exits 0 and prints nothing. A missing DLL fails with a
`StateError` naming the path it searched. A missing/renamed input fails while
reading the JSON. A file of a few kilobytes instead of ~9 MB means the verses
were not written.

To check the contents, open the file with the same generated model
(`lib/objectbox.g.dart`) and assert `Box<Verse>().count()` and
`Box<BibleVersion>().getAll().first.code`; Genesis 1:1 is a good spot check.

## Adding a translation

1. Drop the JSON into `input/<code>.json`.
2. Run the converter with `--code <code> --output outputs/<code>.mdb`.
3. Add the file to whatever bundles the compiled DBs for the app.
4. No code change is needed: `model.dart` and the reader are translation
   agnostic, and `versionCode` is the extension point.

## Changing the model

`lib/objectbox.g.dart` and `lib/objectbox-model.json` are generated and both
are committed. After editing `lib/model.dart`:

```bash
dart run build_runner build
```

ObjectBox assigns entity and property ids from `objectbox-model.json`; keep it
in version control and resolve conflicts in it per the ObjectBox docs rather
than deleting it, or previously compiled `.mdb` files stop matching the model.

## Input format

```json
{
  "metadata": {
    "name": "Authorized King James Version",
    "shortname": "KJV",
    "module": "KJV",
    "year": "1611",
    "copyright_statement": "...",
    "lang": "en",
    "lang_short": "en",
    "module_version": "1.0",
    "italics": 1,
    "red_letter": 1,
    "strongs": 0,
    "paragraph": 1
  },
  "verses": [
    { "book": 1, "book_name": "Genesis", "chapter": 1, "verse": 1, "text": "..." }
  ]
}
```

Metadata is mapped field by field onto `BibleVersion`
(`json_reader.dart::mapMetadata`): name, code, short name, language, source
module, year, publisher, owner, copyright statement, url, lang, lang short,
module version, description, copyright, citation limit, restrict, italics,
strongs, red letter, paragraph, official, research, audio structure. Absent
strings become `''`, absent numbers `0`, absent optional strings `null`.

Verses map to `versionCode`, `book`, `chapter`, `verse`, `text`, `bookName`.
`book`, `chapter` and `verse` stay integers; `text` is stored verbatim.

## Implementation notes

- Verses are written with `putMany` in batches of 1000, then the store is
  closed so the file is fully flushed before it is copied.
- `converter.dart` copies `<temp store>/data.mdb` to `--output` and creates the
  output directory if needed. Copying the store *directory* is not a thing —
  only the data file is the database.
- Nothing here imports the mobile app. The models are deliberately separate;
  the app has its own model for the rows it writes.
- `input/` is committed on purpose: the compiled `.mdb` files must be
  reproducible from the same sources.
